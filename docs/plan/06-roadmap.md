# Galaxy milestones

Outcome-based sequence, with no calendar-day allocation. The operator owns scheduling and the
October 21 delivery deadline. This roadmap covers the game only; portfolio has its own roadmap.
Galaxy takes priority. The assistant has no milestone, spike or prerequisite.

| Milestone | Delivery | Acceptance / review |
| --- | --- | --- |
| G M0 | Corrected game-owned plan, entry flow, ownership and open design status | Separate game commit; no application scaffolding; provisional ideas clearly labelled |
| G M1 | Toolchain/layout, configurable routes, diagnostic renderer lab, draft recovery, data contracts, emulators, deny-all rules tests and build/release foundation | Reproducible local checks and explicit fixture/emulator modes; entry contracts support name, viewing/actions and optional creation; cloud preview only when verified |
| G M2 | Dedicated naming, visual and interaction design session | Operator compares images and executable PoCs, expands/revises ideas and records agreed decisions; initial sketches are not a closed shortlist |
| G M3 | Small complete experience at intended final quality | Direct QR entry → name → galaxy exploration/actions without creation → optional creation branch; two phones and screen; operator review of beauty, tenderness and feel; no duplicates/loss in targeted recovery tests |
| G M4 | Broader approved depth and community behavior | Add objects/interactions from M2 decisions; targeted security, budget, responsiveness and performance checks per addition |
| G M5 | Game memory and permanence | Stable object pages, timelapse, postcard and season export as agreed; replay matches committed history; sharing/restoration verified on devices |
| G M6 | Event readiness | Actual-laptop performance, prolonged session, load, network/process/context-loss drills, compatible deploy/rollback and runbook verified |

G M3's optional creation branch can establish one finished planet with editing, launch,
recognition and return. Do not force visitors to create to participate, and do not implement
unapproved interaction semantics just because they appear in the sketches.

Reliability starts in M1/M3; M6 exercises the assembled system. A green build does not prove
visual quality, a fixture does not prove multiplayer, and emulator success does not prove a
deployed configuration. Report each kind of evidence honestly.

Each implementation milestone uses a versioned branch/PR, with tests and review scoped to its
changes. M0 delivers separate documentation commits without application implementation. No dates or legacy
version labels silently reactivate assistant work or bypass the design session.
